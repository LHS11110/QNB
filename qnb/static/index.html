왜 QNB인가

에이전트의 속도와 인간의 이해력 사이의 간극을 메우다

형식 증명의 생산 속도는 이미 사람의 독해 속도를 넘어섰습니다. QNB는 증명을 읽고, 검증하고, 이어 쓰는 방식을 근본적으로 가볍게 재설계했습니다.

작업 방식 비교

수천 줄을 한 번에 실행하는 대신, 검증된 단위만 연결합니다

기존 단일 파일 Lean 워크플로우
  • 수천~수만 줄 전체를 로컬 PC에서 매번 빌드해야 해서 일반 PC로 따라가기 버거움
  • 코드와 자연어 설명이 분리되어 에이전트가 작성한 증명의 핵심 아이디어를 파악하기 어려움
  • 앞부분 수정 시 전체 파일이 재검증되어 병렬 실험이 느림
QNB 노트북 + 증명 DB 워크플로우
  • 노트북의 서로 다른 Lean 4 셀에서 독립·병렬로 정리와 정의를 검증
  • 코드 셀 사이에 마크다운 해설과 Python 수치·시각화 셀을 자유롭게 배치
  • 검증 통과 정리·정의만 DB에 저장해 다른 노트북·셀에서 즉시 복원 및 증명 트리 탐색

01

격리된 VM 셀 실행

계정별 경량 VM에서 선택한 Lean 4 셀만 빠르게 타입 검사합니다. Python Jupyter 셀과 VM 터미널도 동일한 WebSocket으로 연결됩니다.

02

검증 정리·정의 정규화 저장

통과한 theorem, def, abbrev와 의존성 및 정규화된 명제를 SQLite·PostgreSQL에 저장해 중복을 제거하고 재사용 가능하게 만듭니다.
